# 三菱工艺场景验收

从工艺要求独立得到预期，再对照程序。不要按程序现状反推一份必然通过的测试。先确认机型、输入有效极性、程序身份和已确认的暂停/复位约定。

## 设计场景

建立“要求 → 输入刺激 → 预期输出/步骤/数据/时间 → 证据”的对应关系。

- 正常流程检查相关输出与不应动作的输出，以及数据结果，不只看最后一步。
- 按本题风险选择传感器不到位/矛盾、物料占用、超时、误操作、故障中启动与恢复等场景。不要为不存在的设备编造信号。
- 传感器变化要有工艺依据。手动注入的限位只能证明给定输入条件下程序的反应，不能冒称真实机械自动反馈。
- 连续按键优先等待程序接收标志确认按下和松开；X 回读为0不能证明 PLC 已扫描松开。没有此标志时记录采用的等待假设。
- 计时阈值依据定时器基准、扫描和采样误差设置。`min_delay_ms` 从当前步骤输入写入完成后起算，不能套用上一测试步骤的起点。

## 当前批量接口

```python
gx_simulator_verify(steps=[
    {"label":"确认启动", "inputs":{"X0":1}, "expect":{"M10":1}},
    {"label":"确认松开", "inputs":{"X0":0}, "expect":{"M10":0}},
    {"label":"延时动作", "expect":{"Y0":1},
     "min_delay_ms":100, "timeout_ms":2000, "hold_ms":300}
], forbid=[{"Y0":1,"Y1":1}], sample_ms=20, confirm=True)
```

M10 只是示意，须换成本程序真实的接收反馈。数据期望可用步骤的 `types` 指定 int16/uint16/int32/uint32；如 `expect={"D10":-123456}, types={"D10":"int32"}`。

参数边界：1..64步；每步 timeout_ms 为50..5000、min_delay_ms 为0..timeout_ms、hold_ms 为0..10000；整批 timeout+hold 总和最多60000ms；sample_ms 为5..200。保持中断立即失败；forbid 在等待及保持期间采样，最多32组，其地址与带类型地址不能重叠。

执行前检查整批参数。不给 confirm 的调用只会拒绝执行，不能当作场景参数已经校验通过。

## 执行与判定

复用已验证的工程哈希、原生检查和仿真入口。当前已授权后台执行时按原授权执行；保留用户正在 RUN 的实例和未保存修改，不切换前台、不用全局鼠标键盘。

使用 gx_simulator_* 操作真实虚拟 CPU；写入仅限虚拟 X。不要改用 plc_* 通道或覆写 Y/M/S 来制造通过结果。失败即停止后续输入，记录失败原因、实际值、步骤和计时，再按已授权的收尾策略处理。

报告覆盖到的要求、成功及故意失败用例、未测项、总耗时、采样次数及最大间隔。两次采样间的短脉冲、跨地址原子快照和实体机械状态都不能据此宣称已证明。
