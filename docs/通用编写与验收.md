# 三菱通用编写与验收

当前原生写入及真实仿真核验范围：FX3U/FX3UC、GX Works2 1.620 与已校验哈希的 FX Simulator2。保留原有 API；连接中的旧 MCP 服务需重连后加载新版。

## 三菱语义检查

`gx_program_validate`、`gx_lint_program` 和 `gx_trace_device` 现在区分普通 OUT、SET/RST、步骤转移、定时器/计数器复位及不同 STL 状态复用输出。

- 普通回路或同一 STL 状态内多处驱动仍提示 `DOUBLE_COIL`；正常 SET/RST 配对单独说明执行顺序。
- 跨 STL 状态复用输出给出语义说明，不能由此推断并行路径互斥或设备安全。
- 提示相邻转移步骤复用同一定时器、当前程序缺失目标状态、重复 STL 定义，以及未找到显式 RST 的保持位。
- `writeOnlyDevices` 是供核对的清单，外部设备输出等只写设备不能直接判定为无效代码。

## 数据动作与比较条件

结构化数据动作使用 `instruction` 与 `operands`，不能混用 `out/preset`。现有 OUT/SET/RST 格式继续可用。

```python
rungs = [
    {"logic": "X0", "instruction": "MOV", "operands": ["K12", "D0"]},
    {"logic": "X0", "instruction": "ADD", "operands": ["D0", "K3", "D2"]},
    {"logic": "X1", "instruction": "DMOV", "operands": ["K-123456", "D10"]},
    {"logic": {"compare": {"op": ">=", "left": "D2", "right": "K15"}}, "out": "Y0"},
]
gx_program_prepare(name="data", cpu="FX3U", rungs=rungs)
```

支持 MOV/DMOV、ADD/SUB/MUL/DIV 及其 D 前缀版本、CMP/DCMP、INC/DEC/DINC/DDEC。比较条件可组合 and/or，运算符为 =、<>、>、>=、<、<=，`bits` 可为16或32，默认16。

本批结构化操作数限定 D/T/C 及 K/H 常量，数据目标为普通 D，CMP/DCMP 目标为连续三个 M 位。校验常量位宽及结果隐含占用的连续地址；例如 MUL 写两个 D，DMUL 写四个 D。特殊/变址/打包位寻址未纳入该结构化接口。

原生 SFC 的公共回路、步骤动作及转移条件同样支持这些结构。普通梯形图原生源码写入后仍须完成整工程编译；SFC 原生写入保留现有一次编译、检查、保存与完整读回关口。

## 仿真读取数据

```python
gx_simulator_read(devices=["D0", "D10", "C0", "CN0", "CN200"],
                  types={"D0": "int16", "D10": "int32"})
```

支持 D0..D7999、C0..C255 触点及 CN 当前值。D 默认 uint16；CN0..CN199 默认 uint16，CN200..CN255 默认 int32。显式类型为 uint16/int16/uint32/int32；32位 D 读取连续两字，起点至多 D7998。T/TN 等旧地址与默认返回方式保留。

数据读取不开放寄存器写入；仿真输入写入仍限于虚拟 X 的0/1。浮点数、特殊 D 及其他仿真版本未纳入本批支持。

## 通用时序验收

```python
gx_simulator_verify(steps=[
    {"label": "程序确认启动", "inputs": {"X0": 1}, "expect": {"M10": 1}},
    {"label": "程序确认松开", "inputs": {"X0": 0}, "expect": {"M10": 0}},
    {"label": "延时动作并保持", "expect": {"Y0": 1},
     "min_delay_ms": 100, "timeout_ms": 2000, "hold_ms": 300},
], forbid=[{"Y0": 1, "Y1": 1}], sample_ms=20, confirm=True)
```

M10 是此示意程序自行实现的输入接收标志，其他程序须替换为其真实反馈。输入回读为0不等于程序已扫描松开；连续计数等操作应验证程序确认，不能只反复调用短脉冲。

- `timeout_ms` 等待首次匹配；`min_delay_ms` 限定该步骤输入写入完成后的最早匹配时间。
- 首次匹配后持续检查 `hold_ms`；中途不匹配立即失败，不重新开始计时掩盖中断。
- `forbid` 在整批采样时检查禁止组合，包括等待和保持区间。其地址与带类型期望地址不得重叠。
- 先校验全批参数，再开始写输入；失败即停止后续动作。失败原因含 too_early、hold_broken、timeout、forbidden_combination。
- 返回步骤证据、采样次数、最大采样间隔及至多256条变化记录。仅能证明采样观察，不能排除两次读取间的短脉冲，也不保证跨多个地址为原子快照。

## 嵌套逻辑续修

ANB/ORB 解析原先只保存一层待合并块，第三次 LD 会覆盖分支，导致合法条件被误报为缺失块。现按后进先出保存全部待合并块，与 MPS/MRD/MPP 的分支记忆分开。遗漏合并指令不能静默丢弃条件。

FX 校验按三菱 JY997D16601R 第7.6、7.7节限制最多8个未合并的 LD/LDI 块；这是同时暂存数量，并非整个程序只能有8次分支。其他 CPU 的深度边界未据此推断。

`examples/fx3u_data_operations.py` 的 Y20 直接采用原来失败的条件：`!M301 & !X21 & ((M300 & !X24) | (X24 & X25))`，不再借 M306/M307 拆分。新增真值表、官方手册示例、分支恢复、遗漏合并和8层边界测试；全套507项中463通过、44项环境门控跳过。新工程原生编译、完整检查及图形/源码/编译结果读回通过，零错误零警告，模板保持原样。

真实 FX Simulator2 的37次 MCP 调用通过，包含14步模式恢复与四类故意失败判定；隔离桌面完整验收29.294秒，未切桌面、未发送全局输入，仿真已正常结束。默认桌面原本没有 GX 工程窗口。验收前后的前台句柄不同，因此不宣称前台句柄始终不变；未激活用户 GX 窗口，验收软件始终位于其专用桌面。

## 连续输出条件追踪续修

三菱 JY997D16601R 第7.2、7.3、7.8节允许连续输出及 OUT 后继续串联接点。共享解析器现在保留已经输出的逻辑，后续 AND/ANI/INV 接着计算；新的独立 LD 重新加载条件，MPS/MRD/MPP 与 STL/RET 的边界继续分别处理。条件追踪、布尔预览与校验复用此修复，未改变原生 PLC 指令。

例如 `LD X0; OUT Y0; OUT Y1; AND X1; OUT Y2; LD X2; OUT Y3` 现在追踪为 Y1=X0、Y2=X0&X1、Y3=X2。结构化回路省略 logic 仅表示不插入 LD，不会自动变成一条独立的常真回路。

9项新增用例先复现失败；修复后定向155项通过，全套516项中472通过、44项环境门控跳过。独立测试工程补入原始连续输出指令，仍经过现有原生编译、检查、保存、完整读回，零错误零警告；未扩展生产 SFC 接口。

真实 MCP 从保存工程读回指令再执行条件追踪，核对 Y31=X30、Y32=X30&X31、Y33=X30&X31&!X32、Y34=X33。模拟器16种输入组合全部通过，另保留14步模式恢复及四类反向验收。成功轮43次MCP调用，完整后台验收36.327秒；首次测试参数把一个期望写为布尔值，接口严格拒绝，修正为0/1后复测通过，首次记录保留。

两轮均未切换隔离桌面、未发送全局鼠标键盘输入，模拟器已正常退出。成功轮前后前台句柄不同，不宣称句柄始终未变。实体PLC与采样间瞬变未据此验收；原有MCP连接需重连后加载修复。

## 不动作诊断

新增 `gx_diagnose_output(name, device, snapshot=None)`。name为工作区内的程序名，device目前限FX3U/FX3UC的Y/M位输出。省略snapshot时只读现有FX Simulator2，不启动、停机或写入；提供snapshot时完全离线，不访问模拟器。

```python
gx_diagnose_output(name="data", device="Y0")
gx_diagnose_output(name="data", device="Y0",
                   snapshot={"X7":1, "X10":1, "Y0":0, "M8000":1})
```

示例中的data须替换为实际程序名。快照为原始地址到整数值的映射；位地址只接受整数0/1，拒绝布尔值、越界值和同地址别名重复。M8000用于核对CPU运行状态，缺失时明确列入缺失信息。

返回实际值、所需采样地址、设备注释、逐写入点证据和未满足条件树。`unmet.join=all`表示全部条件，`any`表示任选一路，不能把不同可选支路当成同时必需。常开、常闭、INV与STL步骤条件可求值；缺失值不默认当成0。

状态包含blocked、active、unknown、cpu_stopped、condition_disagrees、history_required、multiple_writers、unsupported_context和no_writer。锁存/脉冲/数据指令写入、多写入、边沿、不支持的数值寻址与复杂控制流会保留未知或需要进一步核对的信息，不推断执行历史。active只表示逻辑输出采样为1，不代表机械动作到位。

所选程序的programSha256与采样来源独立记录，programMatchVerified始终明确为false：工具不会假定工作区程序与实际仿真版本对应，调用者须先核对工程。采样非原子，不能排除两次采样间的瞬变，也不能据此判断接线或机械硬件故障。

本轮18项诊断测试覆盖布尔分支、步骤、未知信息、边沿/比较、锁存/多写入、注释、严格参数及真实stdio发现调用。全套541项：497通过、44项环境门控跳过。隔离真实验收47次MCP调用通过，其中3次只读诊断核对“X7许可阻断→输出动作→X10常闭互锁阻断”，诊断前后输入相同，原有工艺验收保留通过；完整流水线49.316秒，后台28.499秒。新工具随软件包交付，旧MCP连接须重连发现。

## 改动影响报告

新增只读工具 `gx_change_impact(before_name, after_name, limit=50)`，两个名称均为已存工作区程序，目前核验FX3U/FX3UC。工具不修改工程、不编译、不打开软件或访问模拟器/PLC。

```python
gx_change_impact(before_name="before", after_name="after")
```

调用前先将修改前后版本分别存成符合工作区命名规则的程序名。报告给出两版程序哈希、指令变化、发生变化的写入点、变更引用及已知依赖链中的影响候选，分类列出输出、步骤、定时/计数器与寄存器。T/C沿用已有交叉引用的TN/CN归一化名称，明细保留原始指令。

局部接点修改先追踪该回路写入，再追踪其下游；不会仅因出现X0字样就把全部X0使用点都认定为受影响。改变读取地址时，`changedReferences`与`registersToReview`单列待核对地址，不将它们当成整个软元件被改写。DMOV等指令的隐含连续字、CMP/DCMP结果位、16/32位比较、STL步骤、级联输出和MPS分支均使用现有解析及交叉引用构建依赖。

`analysisComplete=false`表示存在未覆盖的控制流或寻址；此时扩大为本程序全部已知写入候选并列出未解析项。即使为true也只覆盖所选程序内的已知静态关系，不证明语义等价、外部HMI/通讯映射完整或运行安全。

`retestRecommendations`按输出、步骤、定时、计数和数据给出检查建议，`runtimeVerified=false`，不把建议记成测试通过。limit为1..200，仅限制变化及证据明细；完整地址分类仍保留，并显式报告明细截断。行号从1开始，原始差异范围沿用0起点、右端不包含的区间。

本轮17项定向案例及全套558项检查：514通过、44项环境门控跳过。49次真实MCP调用通过，静态案例确认T0设定K2改K3后候选为T0与Y2；该候选版本未写入仿真，原有已编译程序仍完成全部仿真回归。完整流水线66.548秒，其中后台33.579秒。软件包已更新，旧MCP连接须重连发现新工具。

## 调试交付档案

新增 `gx_handover_export(name, path="")`，为所选存储程序新建ZIP。默认写工作区handover目录，指定path时须为现有目录内尚不存在的.zip文件；拒绝覆盖和符号链接。源程序不变，不启动、停止或读取模拟器/PLC。

资料包括程序IL、版本/CPU/注释、I/O清单CSV、软元件引用、STL步骤及置复位清单、静态检查、本会话证据、现场信息待填项、交付说明和文件SHA256清单。CSV使用UTF-8 BOM并转义可能作为公式执行的注释；原始注释保留在JSON。ZIP写好后校验CRC及逐文件读回，再发布新文件。

```python
gx_simulator_verify(steps=[{"expect":{"Y0":0}}], confirm=True, project_name="demo")
gx_handover_export(name="demo")
```

示例中的demo须替换为实际工作区程序名。verify可选project_name将该次真实调用绑定到工作区代码版本；未传时旧返回结构保持原样。诊断与影响分析只增加本地内存记录，不写程序或自动重跑验收。影响记录分别标注before/after角色，离线诊断保留provided snapshot来源。
