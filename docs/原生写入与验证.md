# 原生写入、性能与验收边界

## 实际写入路线

`gx_program_create` → `gx_program_validate` → `gx_write_project` → `gx_gxw_open`。

写入工具将指令编码为 FX3U 简单梯形图 `.Program.pou`，经 Windows IStorage API
写入私有临时副本，更新对应历史行的长度和已识别校验值。只有源码读回相同、其他内外层
数据流逐一相同时才交付新文件。原始模板和已有输出均不可覆盖，不调用桌面自动化。

SFC 输入被编译为 FX3U 原生 STL/RET 步进指令，具备步骤、动作、转移和门控分析。
输出文件仍采用简单梯形图程序格式；尚不生成原生 SFC 图形画布。
当前源码与 `.res` 编译缓存分开报告，`requiresCompile=true` 不等于已编译。

## 已完成验证

- 原始 95 项回归通过后开始修改；新增失败测试覆盖 CPU 丢失、八进制和部分解码误报。
- 原生文件写入、增长和缩小、非目标流保持、源文件不变、未知指令拒绝、中文代码页等回归。
- 真实 MCP stdio 握手列出 28 个工具，分别调用梯形图和 SFC 创建、原生写入与读回。
- 顺启逆停使用独立扫描执行器检查：正序启动、逆序停止、启动中停止、停止优先、重复按键、
  停止中重启被忽略、启动键持续保持不误重启；梯形图与 STL/RET 输出序列一致。
- 简单控制 `LD X10 / OUT Y1 / END` 的原生输出经 GX Works2 打开，标题显示 MAIN 3 步；
  转换保存后 `.res` 与 `.Program.pou` 均解码为这三条指令，源代码和编译缓存一致。

## 性能统计方法

性能基准包含编码、临时文件封装、源码读回、全部非目标数据流比较、输出落盘。
普通梯形图和 SFC 各连续写入 10 次，报告中位值、最小值、最大值与 20 次总端到端耗时。
该基准启动 GX Works2 实例数为 0，computer use 调用为 0，截图为 0。
首次原生写入为 297.63 ms；完整分布保存于交付包的 `性能与验证.json`，不冒充软件编译耗时。
