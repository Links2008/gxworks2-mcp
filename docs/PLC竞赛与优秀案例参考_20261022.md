## 实际程序资料

### Festo MPS：最接近当前机械手的 SFC 案例

[厂家程序目录](https://ip.festo-didactic.com/Infoportal/MPS/Software/EN/PLC.html)提供[三菱 FX1N V2.2 示例包](https://ip.festo-didactic.com/Infoportal/MPS/Data/MPS-C_Mitsubishi_FX1N_V2.2.zip)。本次已下载并读取外层说明、内嵌归档目录和 FX1N_readme.txt，没有执行其中的 EXE。说明要求 GX IEC Developer 6.01，使用 Project Restore 恢复；文件更新记录为 2006-04-04。

| 包内原文件 | 厂家说明中的站点 | 可继续研究的主题 |
|---|---|---|
| 04_HA_AS.PCD | Handling，Pic-Alfa | 搬运顺序、工位条件与夹持过程 |
| 10_PP_AS.PCD | Pick & Place | 取放分步、移交条件 |
| 09_SO_AS.PCD | Sorting | 检测结果与分料动作的对应 |
| 05_PU_AS.PCD | Buffer | 上下游可用条件、等待与放行 |
| 03_BE_AS.PCD | Processing | 加工动作与完成确认 |

说明明确该包的站点程序有 SFC 版本，部分另有 FUP 版本。FUP 是 FBD（功能块图），不能误写成 LD（梯形图）。PCD 是旧工程格式，本次只核对归档与元数据，未读出内部程序、恢复工程或在 GX Works2 编译；不能宣称已经分析其转移或联锁实现。它是厂家示例，未发现其为获奖选手提交程序的证据。

下载包 SHA256：`42439a8696a40f70e342d6e4fbe8a2a5c7e1f3e9b93eff6578e02a303e3b6553`。这组文件是适配验证候选，不直接进入生产示例。

### Beckhoff PackML：已有可读源码的工程案例

[原作者示例仓库](https://github.com/Beckhoff-USA-Community/PackML_PLC_Example)使用 MIT 许可；本次读取 MAIN.TcPOU、FB_Cylinder.TcPOU 和 FB_EquipmentModuleTemplate.TcPOU。它是 TwinCAT/ST 示例，不是大赛获奖程序，也未在本机执行。

- 可借鉴：区分动作请求、动作执行中和完成状态；初始化与循环处理职责分开。小型 FX 题目只取有用原则，不移植整套面向对象框架。
- 气缸示例是单线圈阀，使用定时器估计伸出/缩回完成，默认各 1000 ms；这不是实际到位传感器反馈。不能照搬到双线圈阀或称为实测到位。
- 同扫描收到伸出和缩回请求时，源码的缩回处理在后，不是显式拒绝冲突。命令冲突策略仍须由具体设备要求决定。
- MAIN 中存在调试断点保持输出的设置，不作为当前机械手安全停机方案参考。

## 直接用于编写与 MCP 验收的规则

| 参考启发 | 在当前项目中采用的做法 |
|---|---|
| 按书面要求考核功能 | 先列“要求→输入刺激→预期输出/步骤/时间→证据”，从题目独立得到预期，避免让程序与测试犯同一种错 |
| 多站集成与非目标设备隔离 | 每步检查所有相关输出，确认无关执行器不动作；分站通过后再跑完整流程 |
| 初始化与就绪确认 | 区分进程存在、虚拟下载完成、CPU RUN、原点满足及工艺就绪；按键以程序接收证据确认，不能只看输入回读 |
| 正常与异常操作均需考核 | 按本题要求覆盖正常循环、工位占用、暂停/续行、急停与复位；手动模式只在题目要求时增加 |
| 生产周期计时可暂停 | 西门子杯样题要求意外停止不继续计 C/T。借鉴明确计时语义；本题继续沿用已确认的暂停冻结、夹紧/松开各 1 秒，不自动改变工艺 |
| 命令与反馈分开 | 按钮已按下不等于动作完成；有到位反馈就核对反馈，只有时间估计时明确标注假设与校准需求 |
| 故障排查 | 对需求规定的缺失/矛盾限位、超时、占用和异常复位做针对性测试；失败证据包含当前输入、输出、步骤、计时及失败条件 |
| 语言服务工艺 | 顺序动作适合 SFC；少量布尔联锁适合 LD。只在必要位置组合，不为语言统一增加程序 |
| 厂商语义不同 | FX 状态转移依据[三菱编程手册](https://dl.mitsubishielectric.com/dl/fa/document/manual/plc_fx/jy997d16601/jy997d16601r.pdf)；步骤唯一性断言限于本题稳定的单路径状态，不泛化到并行分支或扫描中间态 |

## 后续开发的取舍

当前模拟器工具已支持批量 X 输入及 X/Y/M/S/T/TN 读取，优先用现有工具和一次验收入口表达上述用例。若要无人值守模拟真实机械反应，后续最小扩展是按实际输出驱动限位变化的独立设备模型，并可注入卡滞；不能按预计步骤无条件送限位。这是待实现方向，本次未新增模型或扩大工具接口。

电梯群控涉及的多设备对象、数据寄存器和通讯，以及竞赛 HMI/物联网，不属于当前 FX 机械手工具的已验收范围。不因参考案例引入另一套编译器、完整 PackML 框架或新 GUI 流程。

## 三菱通用 MCP 改进方向（2026-10-22 补充）

用户明确要求学习三菱，程序类型不限于机械手等已有示例。本节为后续优先入口；前文其他厂商资料保留为历史检索记录。

### 本轮实际学习与核对

- 已下载并阅读[三菱 FX 编程手册 JY997D16601-R](https://dl.mitsubishielectric.com/dl/fa/document/manual/plc_fx/jy997d16601/jy997d16601r.pdf)中小车往返、顺序启停、大小球分拣及 SFC/STL 对照图。重点位置：印刷页 759–764、780–785、799–800，PDF 页码比印刷页多 2。
- 可借鉴的语义：夹持 SET/释放 RST、分支汇合、方向互锁；M8040 禁止步骤转移时，步内程序仍执行；同一定时器不应在相邻 STL 步重复驱动。此处是手册分析，未作为新程序仿真通过的结论。
- 该版分拣图存在待核对处：SFC 的 S23 转移使用 X003，而配套 STL 图/指令表标为 T3；梯形图的启动条件标 X007，配套指令表和 SFC 为 Y007。因此自动转写需要交叉核对原件，不能仅凭 OCR 结果发布。
- [三菱电机杯官方报道](https://fa-faq.mitsubishielectric.co.jp/fa/the-art-of-manufacturing/focus/world-roundup18/report02.html)可确认第十六届系统应用赛的一等奖及加工系统、数字孪生任务；本轮未取得其 PLC 源程序。
- 已下载并抽看[一等奖作品《青花》公开论文](https://fa-faq.mitsubishielectric.co.jp/fa/the-art-of-manufacturing/focus/world-roundup18/blue-and-white_jp.pdf)第 1、2、7、8 页：使用三菱工业机器人及控制器，属于系统集成设计资料，不作为 FX 梯形图源码。

### 已有基础与实际缺口

只读检查了 server.py、author.py、analysis.py、validate.py、native_sfc.py 与 simulator.py。交叉引用、条件追踪、版本补丁、批量准备、SFC 原生编译读回及真实仿真验证已存在，应在其上改进。

| 优先级 | 通用能力 | 本项目现状与候选改进 | 适用程序 |
|---|---|---|---|
| 第一批 | 三菱语义检查 | 当前重复线圈检查按写入次数提示。区分普通 OUT、SET/RST、STL 状态上下文与并行路径；补充定时器复用、转移条件和复位检查，无法证明的情况标为待核对 | 启停、自保持、顺控、分拣及多模式控制 |
| 第一批 | 数据运算的结构化编写与验收 | 结构化动作目前仅 OUT/SET/RST；助记符路径另有部分运算支持。按实用需求补 MOV、比较、运算等，并核对原生编码、编译及读回支持；真实仿真另需验证 D/C 与有符号数、32 位等数据解释 | 计数、配方、设定值、计算及模拟量处理逻辑 |
| 第一批 | 通用时序验收 | 现有 verify 为输入变化后等待值相等。补保持时长、顺序、时间窗口及采样中的禁止组合检查；验收脚本只替换本题 I/O 和要求，保留原生编译等必要关口 | 不同设备的正常、异常与恢复流程 |
| 第二批 | 实时原因诊断 | 现有条件追踪主要是静态结构。结合当前输入、步骤与计时，定位未满足条件；涉及保持状态或历史时显式说明证据不足 | “输出为何不动作”“卡在哪一步” |
| 第二批 | 变更影响与精简回归 | 复用已有交叉引用、版本补丁及文件哈希；列出受影响设备、步骤和关联测试，减少重复测试与界面操作，保留必要整工程原生检查 | 已有工程局部修改及调试 |
| 按需扩展 | 更广的 SFC 拓扑 | 原生图形当前为单路径、每步一至两路选择，未支持并行。多路选择、并行与汇合应在有对应需求时扩展，并用厂商执行结果核验 | 多工位并行、装配、批处理 |

每项支持范围分别记录“能表达、能检查、能原生写入、能编译、能仿真”，不能从 CPU 名称可接受或能解析某条指令，推断后续链路已支持。数据类型与指令细节按具体 CPU 官方手册核对。

本轮以两个独立小程序复现了现有 DOUBLE_COIL 提示：正常 SET/RST 配对，以及不同 STL 步复用 Y0，均被描述为后者覆盖前者。这是改进语义诊断的证据，未修改检查器、运行 PLC 程序或扩大仿真写入权限。候选改进尚未实现；不据此宣称程序效率或端到端耗时已经提升。
