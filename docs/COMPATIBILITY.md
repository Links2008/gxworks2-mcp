# 兼容性边界与分层验收

## 已实现与明确拒绝

| 路径 | 支持范围 | 遇到范围外输入 |
| --- | --- | --- |
| 离线工程读取 | `.gxw` OLE2 容器；程序体逐项报告覆盖率 | `.gpj` 明确拒绝；未知程序体不能作为完整源码写回 |
| 梯形图 / STL 原生源码写入 | 已验证 FX3U 指令与容器；Windows IStorage | 未知指令拒绝；新文件发布前源码读回与非目标流核验 |
| 原生 SFC 图形 | GX Works2 1.620.0.1 / FX 14.67；固定双块模板；顺序、双路选择、显式跳转 | 未知 DLL 哈希、并行输入、未知符号、重复编号、孤立格点、连接差异拒绝 |
| ST、任意原生版本与模板 | 尚未实现 | 不猜测编码，不宣称兼容 |

`.gpj` 不能通过改扩展名变成 `.gxw`。在原工程软件中创建受支持的副本后，仍须检查容器和各程序体的解析状态。副本不应覆盖原工程。

原生 DLL 白名单不等同于为所有工程版本建立了白名单。纯文件读回按已知结构校验；没有经过证明的新格式不能扩展为写入支持。

## 本轮自动化验证

使用独立合成格点、合成不受支持库内容与最小文件头测试拒绝路径，不新增客户工程或厂商 DLL。

- 整图预检覆盖不可达的未知 / 并行符号，不再只比较可读子图。
- 重复步骤和转移编号显式拒绝，避免字典覆盖掩盖歧义。
- 已知顺序与双路选择的正向读回回归保留。
- `.gpj` 在 OLE 解析及 store 导入前拒绝，保留 `.gxw` 原有格式检查。
- 未知原生库在编译器或辅助进程启动前拒绝。

命令：`python -m pytest -ra`。Linux 上 IStorage 测试显式跳过，不是通过；GX Works2 原生集成缺少显式输入时也跳过。原生测试不应仅因提前遇到平台错误而被算作通过。

## 后续 Windows 原生验收：本轮未运行

在已安装 GX Works2 的 Windows 上，以新临时目录操作并保留原模板哈希：

1. 安装项目的 `native,dev` 依赖；执行 `python -m pytest tests/test_native_gxw.py -ra`。验证 IStorage 增长 / 缩小、中文注释、非目标流不变、磁盘损坏拒绝、失败清理。
2. 指定 `GXWORKS2_INSTALL_ROOT` 和 `GXWORKS2_SFC_TEST_TEMPLATE`。模板须为授权使用的最小 FX3U/FX3UC 双块样例，不使用生产线数据。执行 `python -m pytest tests/test_native_sfc.py tests/test_sfc_readback_sequence.py -ra`。
3. 核对准确的安装版本与 DLL 哈希、原生检查错误 / 警告数、完整格点读回、源码 / 编译读回、非目标流核验、输出文件及模板哈希。任何新拒绝均保留诊断，先查明格式，不绕过白名单。
4. 执行 `python -m pytest -ra` 与 `python tests/test_stdio_e2e.py`，记录 commit SHA、通过 / 失败 / 跳过数量。原生 9 项历史结果不能替代本轮结果。

## GX Simulator2 行为验收：本轮未运行

隔离于真实 PLC，使用新生成的最小工程。由 GX Works2 打开并转换 / 检查，在 GX Simulator2 验证首次扫描、顺启逆停、启动中停止、同时启停、持续启动不重启和选择分支优先级；逐条记录输入、扫描时序、期望 / 实际输出与诊断。

Python 扫描测试是逻辑回归，不是 GX Simulator2 实测。不得把模拟器当作可直接连接的 MC 端点；本轮不增加 MX Component 集成，不连接、下载或驱动实体 PLC。

## 尚待研究

并行 SFC、ST 和新原生格式需要合法来源的最小对照样例、文档、正反向差分与版本矩阵，之后才能实现对应编解码和原生验收。未知数据继续 fail-closed；不把兼容性加固表述为“全部难点已解决”。
