# 原生 SFC 图形编写及核验

验证日期：2026-10-21。目标为本机 GX Works2 1.620.0.1、FX3U/FX3UC。

## 已验证的路径

`gx_sfc_write` 在一个按需 x86 子进程内完成以下工作：

1. 使用 FX 14.67 原生导出函数创建图形、选择分支、跳转及动作和条件。
2. 生成程序后清空原生对象，再从字节重新解码，逐项对照动作、条件及图形连线。
3. 导入只读模板的隔离副本，通过 Workspace 创建源对象和注册；不直接修改生产工程。
4. 调用 `ChangeSFCProgram`，观察原生完成记录。
5. 对 MAIN 资源执行 `ProgramCheck(-1)`，等待终态，并核对错误、警告及完成记录计数。
6. 仅在检查通过后调用 `SaveProject`、`CreateProjectHash` 和 `ExportOneFileProject`。
7. Python 重新打开导出文件，验证图形、动作及条件；MAIN.res 必须与独立 FX SFC
   转换器生成的程序体逐字节相同，随后才原子发布新文件。

基准对照：已有真实模板的原生重建程序体为 907 字节，与 GX Works2 已保存的 MAIN.res
逐字节相同。顺启逆停使用新生成的程序体，通过本机完整检查，零错误、零警告。

## 运行约束

- 不启动 GD2，不调用 computer use、UI Automation、鼠标、键盘或截图。
- 原生库为进程内加载；没有额外服务、监听端口、守护进程或预热后台。
- 线程锁与进程锁共同串行化原生任务；最多一个辅助进程。首次使用还需顺序运行本机
  .NET 编译器生成缓存程序，源码改变才重新编译。
- 原生辅助进程限时 15 秒，超时由父进程终止并回收；检查失败不发布文件。
- 工作区原生 DLL 的卸载可能等待其内部线程；完成原生保存和诊断输出后，只结束自己的
  辅助进程，避免残留。临时目录通过路径范围和归属标记校验后清理。
- FX 转换器按 SHA256 精确匹配；COM 实际加载路径和 Workspace/ProjectOperation/
  CompilerAdapter 版本均验证为指定安装中的 1.620.0.1。
- 不操作任何实体 PLC。用户真实生产工程只读，不属于本轮验证对象。

FX 原生库 SHA256：
`7915fec25ecf9ab0a2a9ff7072ec23deb6187d83dbe86b885747ba29e4be99b8`。
本机只读 `ProductDataBase2/DataBaseE/Cpu.mdb` 中 FX3UC 对应 PCFlag=520，即 0x208。

## 数据保持和错误处理

原生保存会正常更新源码、MAIN.res、Param.lup、DeviceAssignment.dat、ESCompiler.stg、
CallTree.dat、SystemLabel.sld，以及工程历史、索引和完整性数据。这些变化在返回值中列出。
其余内层数据流必须逐字节保持；未知新增、删除或修改均拒绝交付。

保留工程封装中的原生完整性信息很重要。直接重封装 SFC 数据流后保留旧 Project.gd2
不能构成可交付工程，因此最终写入必须经过原生 Workspace 保存。

已发现并修复的实际问题：S 软元件的 SET/RST 使用专用编码；原生顺控动作中重复输出
线圈会被严格检查拒绝，示例把 Y0/Y1/Y2 集中驱动。初始扫描明确清理旧步骤；启动脉冲
同时受停止和初始扫描抑制，防止同时按启停后在下一扫描延迟启动。

## 顺启逆停验收

输入：X0 启动、X1 停止；输出：Y0、Y1、Y2。T0..T3 使用 100ms 基准、K10。

从实际保存文件读回动作和条件，再执行限定于本示例的扫描模型，验证正常启动、逆停、
启动中两种阶段停止、同时按启停、持续启动、停止中重启、初始旧状态清理。
另以重复输出线圈作为真实原生拒绝测试，并验证保存文件可再次原生打开和继续编辑。
共 9 项原生集成测试通过。

这不等同于完整 GX Simulator2 仿真或实体 PLC 测试。真实扫描周期、旧步 OFF 清理、
输出硬件响应和现场联锁仍属于设备验收范围。

## 范围和速度

支持双块 FX3U SFC 模板、顺序转移、双路选择和显式跳转；不支持任意模板布局、并行
分支或未核验的原生库版本。所有限制均在写入边界显式拒绝。

完整原生生成、编译、严格检查、保存、读回约 6.6 秒；其中转换约 29ms、程序检查约
546ms，较多时间来自原生导入、保存和导出。每次返回 `nativeProjectCompile.timingsMs`。
本机 MCP stdio 端到端写入 6570.32ms，读取 11.21ms，工具发现共 35 项。
纯文件读取的原生进程数为 0。具体端到端实测随交付报告记录。
