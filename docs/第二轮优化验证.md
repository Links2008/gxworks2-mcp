# 第二轮原生写入优化与验证

日期：2026-10-20。基线写入器来自 `bcc791f`，继续使用同一模板、示例程序和读回校验。

## 修改

- 复合文档的内层和外层修改改用 Windows ILockBytes 内存存储。
- 移除中间 CFB 的磁盘写入和重复读取；最终候选文件仍落盘并由独立读取器校验。
- 使用解析时取得的同一份源文件快照，避免写入过程中重新打开模板取得不同版本。
- 保留未知数据流的逐字节比较、原文件保护、输出禁止覆盖和失败临时目录清理。
- 不增加常驻进程，不调用 computer use，不启动 GX Works2，不取消校验或修改系统安全设置。

## 同输入交替基准

每种程序各运行旧、新写入器 10 次，轮换先后顺序，所有写入保留完整校验。
单次耗时覆盖写入函数的全部处理；40 次基准总端到端耗时为 13.071 秒。

| 程序 | 指令数 | 优化前中位 | 优化后中位 | 耗时降低 |
|---|---:|---:|---:|---:|
| 普通梯形图 | 97 | 465.76 ms | 166.73 ms | 64.2% |
| SFC 步进程序 | 44 | 438.62 ms | 162.66 ms | 62.9% |

结果是本机本次测量，不包含模型思考、客户端调度或 GX Works2 编译时间。
原始 40 个样本随交付 ZIP 中的 `第二轮性能数据.json` 提供。

## 验证

129 项测试通过，包括新增加的：

- 复合文档流跨越小扇区阈值的增长与缩小，其他流保持不变。
- 1401 条指令的工程写入后再缩为 END。
- 最终磁盘文件被破坏时拒绝交付，清理临时文件。
- 容器结构有效但非目标流被改动时仍拒绝交付。

真实 MCP stdio 验证列出 28 个工具，并调用梯形图/SFC 创建、原生写入与读回。
该进程仅在检查期间存在，完成后退出。

## 保留的边界

输出仍为待 GX Works2 编译的原生源码。SFC 采用 STL/RET 步进形式；
原生图形画布新建、顺控示例的软件编译验收和实体 PLC 验收仍未完成。
本轮没有新增或宣称通过这些验收。

接口依据：[pywin32 PyStorage.cpp](https://github.com/mhammond/pywin32/blob/main/com/win32com/src/PyStorage.cpp)
与 [PyILockBytes.cpp](https://github.com/mhammond/pywin32/blob/main/com/win32com/src/extensions/PyILockBytes.cpp)。
